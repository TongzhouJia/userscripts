# 谷歌翻译·粘贴自动朗读

在 [translate.google.com](https://translate.google.com) 里粘贴文字后，自动点页面自己的「听取原文」按钮把它读出来。

背英语的时候不用每次都伸手去点那个小喇叭。

## 💡 为什么是「点它自己的按钮」

一开始的思路是调 `translate_tts` 接口自己播，后来改成模拟点击，因为：

- 用的就是谷歌自家的高质量语音，跟手点一模一样
- 不碰内部接口，不会被限流、不用把长文本切成 200 字符的段
- 点击发生在用户手势里，绕开浏览器的自动播放拦截
- 长文本谷歌自己会处理

代价是得跟 DOM 打交道，所以选择器写了四层兜底。

## ⌨️ 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+V` | 粘贴后自动朗读（主功能） |
| `Ctrl+Shift+S` | 手动朗读／停止（切换） |
| `Ctrl+Shift+A` | 开关自动朗读，状态存 localStorage |
| `Ctrl+Shift+D` | 把源文本面板里所有按钮 + 断读诊断打到控制台（F12 看） |

被掐断时也可以直接按 `Ctrl+Shift+S` 手动重读，那是纯切换、不受自动逻辑影响。

## ⚙️ 配置

文件顶部：

```js
const SETTLE_MS  = 400;   // 文字到位后再静置多久才开始等 DOM 安静
const TIMEOUT_MS = 4000;  // 等文字到位的上限
const QUIET_MS   = 700;   // DOM 连续这么久没变动才算「译文渲染完了」
const MAX_WAIT_MS= 8000;  // 等 DOM 安静的上限，超时也照点
const RESUME_MS  = 3500;  // 开播后这么久内就停了 = 被掐断，自动续读
const MAX_RESUME = 1;     // 最多自动续几次
```

**还会被掐断就把 `QUIET_MS` 调到 1200。** 觉得起播太慢就往下调到 400。

不用死等固定时间是因为：脚本会轮询等 `textarea` 里真的出现刚粘的那 30 个字符（去空白后比对），到位了才开始算静置。短文本不用白等，长文本或网速慢时又能等够。新文字没进框就绝不会点，所以逻辑上读不到上一段。

## 🔇 「读一半突然断了」是怎么回事（v3.1.0 修）

谷歌翻译是 SPA，**不会整页刷新**。真正发生的是：译文请求回来时（实测 800ms~2s），它把那一整块 `c-wiz` 重新渲染，朗读按钮连同背后播放音频的 `<audio>` 一起被换掉，声音就在半路没了。

v3.0 只等「文字落进 textarea + 400ms」，翻译还在路上就开读，所以必被后到的渲染掐断。v3.1.0 加了两道防线：

1. **等 DOM 安静再开读。** `MutationObserver` 盯着 `document.body` 的 `childList`/`characterData`，连续 `QUIET_MS` 没有任何变动才认为这一轮渲染结束。判据故意不用「译文出现了没」—— 译文侧的选择器（`ryNqvb`、`jsname="W297wb"`）改版就废，而「安静」不依赖任何 class。超过 `MAX_WAIT_MS` 还在动就照点，慢网别干等。
2. **断读自动续。** 起播后盯 `aria-label`，如果 `RESUME_MS` 内就停了，那不是读完是被掐了，等 DOM 重新安静再读一遍，最多续 `MAX_RESUME` 次。

**怎么确认是不是真刷新：** 断了之后按 `Ctrl+Shift+D`，看这两行——

```
[autospeak] 本次载入是不是读到一半整页刷新的: 否
[autospeak] 上次等 DOM 安静的结果: quiet   (timeout = 页面一直在动)
```

第一行靠 `sessionStorage` 存的开播时间戳判断：整页刷新会让脚本重跑、状态清零，SPA 重渲染不会。显示「是」才是真导航，那得另想办法；显示「否」就是上面说的重渲染。

## 🎯 怎么找到那个按钮

实测 DOM（2026-08）：

```html
<button jsname="UsVyAb"
        aria-label="听取原文"
        data-aria-label-off="听取原文"  data-aria-label-on="停止聆听"
        data-tooltip-label-off="朗读"   data-tooltip-label-on="停止">
```

定位分四层，任一命中即可：

1. `button[jsname="UsVyAb"]`
2. `button[data-tooltip-label-on="停止"]`
3. `data-aria-label-off` / `aria-label` 匹配多语言正则
4. 按钮里含 Material 喇叭图标的 SVG path（`M3 9v6h4l5 5V4L7 9H3`）

而且只在**原文侧面板**里找 —— 从 `textarea` 往上爬到第一个含多个按钮的祖先，这样不会误点译文侧的朗读。

## 🕳️ 已知的坑

- **`VfPpkd-Bz112c-*` 是 Material 水波纹层，不是这个按钮的标识**，页面上每个按钮都有一个，不能拿来选元素。
- **别用「语音」匹配 `aria-label`** —— 麦克风按钮叫「语音翻译」，会被抢先命中。
- **这按钮空输入框时也是 `disabled: false`**，不能靠它判断就绪。
- **它是播放/停止切换**，自动触发时如果正在读，会先点停、隔 200ms 再点开始，保证从头读新内容。所以千万别补发一轮指针事件，等于点两下。
- 谷歌改版可能把 `jsname` 换掉。真读不出来了就按 `Ctrl+Shift+D` 看控制台那张表，照着更新第一层选择器。

## 🌍 界面语言

正则覆盖了中/英/日/韩（`听取|聆听|朗读|listen|聞く|듣기` 等），第 1、2 层选择器则完全不依赖语言。
